# MQTT Trust Gateway 1.4.0

## Device connection health

- Enable optional MQTT connection monitoring per device using an administrator-selected status topic, QoS 1, retained online messages, and a retained offline Last Will.
- View 30 UTC days of uptime in **Trusted Devices**. Unknown time is excluded from uptime and incomplete coverage is indicated in the tooltips.
- Configure offline grace and recovery stability periods. The monitor requires a successful QoS 1 subscription and treats retained replays and monitoring interruptions as Unknown until a new live status arrives.
- Health topics are reserved to their associated identity in the broker ACL. Review each device's publish Rules and apply the pending broker changes after configuring monitoring.
- Device Health Help explains device status publishing requirements and monitoring limitations. Use one MQTT session per identity: multiple sessions can produce conflicting status. Live delivery does not allow the Gateway to verify the sender's retain flag.

## Device identities and certificates

- New devices receive automatically generated immutable IDs; names may be reused. Existing device and certificate IDs remain unchanged.
- Newly created certificate records receive unique IDs. X.509 serial numbers, fingerprints, certificates and keys are preserved.

## Gateway health

- `GET /health` provides a minimal liveness response. `GET /ready` checks SQLite, accepts direct local or private monitoring clients, and rejects forwarded requests. Configure public proxies to block `/ready` and `/healthz`; both responses are non-cacheable.

## Update and compatibility

- The additive SQLite schema migration preserves existing device records, certificates, the CA and broker configuration. Create and verify a backup before updating.
- The coordinated signed updater requires the configured release trust key and a compatible rootless Podman installation. Host Linux, Podman and systemd updates remain outside its scope.
- SMTP and Telegram alerts are not part of this release.
