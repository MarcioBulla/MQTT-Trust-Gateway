# MQTT Trust Gateway 1.0.1

Patch release for secure remote administration behind an HTTPS reverse proxy
when rootless Podman port forwarding masks the proxy's source address.

## Changes

- Added optional `ADMIN_CONTAINER_IP` to pin the admin container to a reserved
  IPv4 address on `mqtt-gateway.network`.
- Documented the matching exact `/32` `TRUSTED_PROXIES` configuration for a
  host-local proxy while preserving loopback-only host port publishing.
- Kept remote HTTP administration rejected; forwarding headers are still trusted
  only from explicitly configured addresses.

## Validation

- `bun run build` completed; Vite reported only the existing large-chunk advisory.
- `bun run test` passed all 41 tests.
- `./gateway update` built and started both rootless Quadlets on the ColdLab test
  host; MQTT broker and admin services reported active.
- Public HTTPS returned HTTP 200 with normal certificate verification; direct
  loopback HTTP remained HTTP 403.
- The generated Quadlet retained the reserved admin IP and the exact `/32`
  trust entry matched it after the installer restart.

## Upgrade

Back up the gateway data and `gateway.env` before updating. Set
`ADMIN_CONTAINER_IP` to an unused IPv4 address on the gateway network and set
`TRUSTED_PROXIES` to the same address with `/32` when the proxy connects through
the host's loopback-published port. Keep the admin host bind on loopback.
