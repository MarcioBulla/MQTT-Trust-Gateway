# MQTT Trust Gateway 1.0.0

First versioned release of the rootless MQTT Trust Gateway administrative console.

## Included

- Vue 3 / Vuetify 3 interface, responsive navigation, reusable lists and light/dark themes.
- Password authentication, TOTP, passkeys with user verification, and step-up authorization for authentication changes and protected information.
- Unified device/certificate management: sign device CSRs, generate complete credentials, generate external CSRs, and import signed certificates.
- Integrated OpenSSL CA, persistent SQLite identities/history, explicit external CA trust, CRLs and broker authorization.
- Device and license archive/delete workflows; device archives have persisted 30-day deletion deadlines.
- MQTT Manager with real-time metadata, protected topics/payloads, publication, QoS, retained-message controls and bounded history.
- Seven days of persistent aggregate traffic history, configurable msg/min or msg/hour axes, and observed queue-drop/publication-failure markers.
- Fourteen editable Light/Dark palette presets, independent Dark-only OLED mode, timezone and chart preferences per account.
- Two essential containers managed through rootless Podman Quadlet. No integrated proxy, step-ca, Certbot, Docker or Compose requirement.
- Configurable broker SANs for hostname verification, optional external proxy documentation, backup/migration guidance and Zephyr examples.
- Apache-2.0 licensing with Marcio Bulla attribution in NOTICE and in the administrative container.
- Six Chromium screenshots in the README; capture data is explicitly documented as isolated demo data.

## Validation

- Frontend production build and 41 automated tests.
- Chromium browser checks for authentication prompts, protected values, chart settings, theme presets, manual colors and OLED.
- Local MQTT/TLS and WSS tests with CA validation and negative certificate cases, MQTT 5/3.1.1, QoS 0/1/2, and A/B ACL isolation.
- Controlled offline-subscriber queue overflow demonstrated real drops with QoS 1 and 2; spaced publications demonstrated normal delivery.
- Local rootless container build, health checks and persistent traffic history after administrative restart.

## Operational notes and limitations

- Back up persistent data and CA keys before updating. Never replace an existing CA automatically. Legacy step-ca migration requires the documented manual review.
- Broker authorization, trust and revocation changes remain pending until applied; applying them restarts the broker and disconnects current MQTT sessions.
- Individual device online status and last activity are unavailable without a verified broker connection feed.
- Traffic totals and drop markers cannot prove processing by individual subscriber applications. msg/min is an hourly average; absent observations remain gaps.
- SMTP email alerts, device Rules and Health Check interfaces are marked WIP.
- Zephyr documentation is included; MCU hardware execution and board firmware builds were not validated for this release.
- Retained-message behavior with every third-party WSS client has not been exhaustively validated.
- Remote administration requires HTTPS. Public reverse proxies are supplied and managed separately by the operator; raw MQTT/mTLS forwarding needs TCP support.

## Installation

```sh
cp gateway.env.example gateway.env
./gateway install
./gateway status
```

See README for bootstrap, certificate provisioning, optional proxies and backups.

## Release workflow

Prepared from a short-lived branch and integrated into main after validation.
The annotated `v1.0.0` tag identifies the approved commit. Future patch work
should start from `main` on short-lived branches and be tagged after validation;
no permanent release branch is kept.
