# MQTT Trust Gateway 1.3.1

## Certificate and license workflows

- Certificate renewal now reuses the public key from the selected certificate. To rotate a device key, use **Add certificate → Sign an existing CSR**; device private keys remain on the device.
- Sensitive certificate actions request step-up verification before opening their action dialogs. **Copy CRT** displays the public certificate PEM with a copy control.
- Trusted-device labels flow down to its licenses; labels added to an individual license remain independent. Deleted license records remain visible and are marked **Deleted**.
- Removed ambiguous certificate actions from the Trusted Devices table, including the generic download and duplicate issue-certificate action.

## Sensitive information and Help

- Sensitive visibility settings are grouped under **Settings → General**. The topbar control reveals or hides protected information across sections; the administrator can configure the reveal timeout and whether losing browser focus hides values.
- The Dashboard first-message guide links to the relevant Help articles, and certificate operation articles reflect the renewal workflow.
- Refreshed the Gateway logo and favicon assets.

## Compatibility

- Existing certificate renewal preserves the selected certificate's public key. No device private key is uploaded or stored by the Gateway.
- This release does not change the MQTT broker protocol or the per-device topic rule model introduced in 1.3.0.
