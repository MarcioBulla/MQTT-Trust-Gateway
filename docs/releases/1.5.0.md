# MQTT Trust Gateway 1.5.0

## MQTT certificate renewal

- Request a device-generated CSR through the configured per-device MQTT PKI topics. The Gateway validates the CSR signature and device identity, then issues a certificate for the registered Device ID.
- Review each CSR manually or configure automatic acceptance for a specific expected CN. An optional scheduler can start one renewal attempt before an eligible certificate expires.
- Save renewal topics independently from starting a renewal. The UI also supports refreshing operation status and choosing the new certificate validity.
- A renewal is complete only after the device confirms activation. The prior certificate is retained during the transition; rejected, rolled-back, and timed-out operations do not revoke it.
- The device must be authorized, connect using mTLS, and have Rules that permit the configured PKI exchanges. Configure the device firmware to use the same topics and payload format shown in **Edit Device → Renew**.

## Certificate revocation and administration

- Revoking an individual local certificate preserves device authorization when another active, trusted, unexpired certificate remains. The Gateway disables the device when no usable certificate remains, and fails closed if local CRL revocation fails or the issuer is external.
- Service log timestamps follow the time zone selected in Settings.
- The renewal Help article explains the request, CSR review, confirmation, and recovery workflow.

## Work in progress

Gateway CA rotation and migration remain WIP. This release does not distribute a new broker CA to devices or change the broker's TLS certificate. Device firmware storage and OTA distribution remain outside the Gateway's scope.
