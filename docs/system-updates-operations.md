# System Updates operations

Run all commands as the rootless Gateway owner inside its user systemd session.
The updater requires Podman 5+, Python 3.12+, OpenSSL and a running user manager.
It does not require root or expose the Podman socket to Admin.

## Enable

First install the source version containing updater support using the existing
source-install workflow. Preserve the existing runtime and CA. Obtain the
release Ed25519 public key through a separately authenticated project channel;
never automatically trust a key merely because it accompanies a manifest.
Set `GATEWAY_UPDATE_PUBLIC_KEY_B64` in `gateway.env` to its base64 SPKI DER value.
Complete any pending one-time key downloads before enabling the controller.

```sh
./gateway updater-enable
./gateway updater-status
systemctl --user status mqtt-gateway-updater.service
```

Enablement briefly replaces the two application containers to mount the narrow
read-only control bridge. It verifies services before and after, and restores
the previous Quadlets if setup fails. A privileged/legacy broker without the
maintenance capability is refused. No CA is generated by the updater.

## Install

Open **Settings → System Updates**, choose Stable/Beta and check for updates.
Review release notes and compatibility, select **Review update**, type the
shown `INSTALL version` confirmation and complete fresh authentication.
MQTT clients disconnect and must reconnect after completion. Progress survives
a browser reload and Admin replacement; inspect **Version history → Details**
for safe stage/error codes. Retained messages and persistent sessions are
included in the stopped-broker snapshot.

A host owner can also request a specific verified release:

```sh
./gateway release-install --version 1.1.1
```

## Recovery and rollback

```sh
./gateway updater-status
./gateway updater-recover
journalctl --user -u mqtt-gateway-updater.service --since today
```

Bare recovery resumes an interrupted operation, but does not repeatedly retry
RECOVERY_REQUIRED. Repair the reported cause (disk space, service configuration,
image availability or damaged recovery storage) before an explicit retry:

```sh
python3 scripts/updater/cli.py recover --operation-id UUID --confirm 'RECOVER UUID'
```

Substitute the exact operation UUID. Each call requests one confirmed retry;
failures return to RECOVERY_REQUIRED. After COMMITTING, recovery only starts
and validates the committed release. It never restores an older snapshot.

**Review rollback** is available only while the current operation's verified
recovery point exists and relevant persistent data has not changed. It requires
fresh authentication, `ROLLBACK previous-version`, and a new safety snapshot.
Host equivalent:

```sh
./gateway release-rollback --operation-id UUID --confirm 'ROLLBACK 1.0.2'
```

If new device, certificate, revocation, configuration or MQTT persistent state
exists, the old snapshot is unsafe and rollback is refused. Do not bypass this
guard or restore old data over newer state.

## Protect recovery data

Snapshots reside in the host user's private updater state, outside web-served
paths. They contain CA private keys and credentials. Use encrypted storage,
restricted backup access and offline encrypted copies. Configure **Recovery snapshots to retain** (2–100, default 5). Cleanup runs
following service operations and preserves current/installed and unresolved
recovery points, so protected snapshots may exceed the count. Displaced runtime
is retained separately. Do not remove images needed by a recovery point.

For an encrypted offline copy, install GnuPG on the host, import the intended
recipient's public encryption key and verify its full fingerprint separately.
The command requires the full 40- or 64-character fingerprint and never
silently overwrites an existing output file:

```sh
python3 scripts/updater/cli.py export-snapshot --operation-id UUID --file "$HOME/gateway-recovery.gpg" --recipient FULL_FINGERPRINT
```

The output is a GPG-encrypted tar bundle containing `snapshot/state.tar.gz` and
`snapshot/snapshot.json`. Both are required for verified recovery. The recipient
must retain their private encryption key outside the Gateway. To inspect an
export in a private directory, decrypt before extracting and verifying:

```sh
umask 077
mkdir recovery-inspect
gpg --output recovery-inspect/bundle.tar.gz --decrypt "$HOME/gateway-recovery.gpg"
tar -xzf recovery-inspect/bundle.tar.gz -C recovery-inspect
python3 -c 'from scripts.updater.snapshots import verify; verify("recovery-inspect/snapshot"); print("Verified")'
```

This is an offline inspection procedure, not an instruction to overwrite a live
installation. Local updater snapshots remain unencrypted; protect their disk
and permissions. Exporting does not replace the local active recovery point.

Host Linux, kernel, Podman, systemd and updater source updates remain separate.
There is no offline release import or automatic installation.
